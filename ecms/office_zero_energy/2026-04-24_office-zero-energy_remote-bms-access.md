# ECM: Remote BMS Access

## Summary

**What:** Enable remote login to BMS for property management team via VPN, cloud gateway, or BACnet/IP tunnelling. At UN Studio Tower, BMS is currently accessible only by the external contractor — property manager has no direct access.

**Why:** Remote access enables fast fault response without site visit. At properties where BMS is contractor-only, every setpoint change requires a paid callout, delaying response and adding cost.

## Estimated Savings
- Indirect (operational efficiency)
- Avoided callout costs; faster fault response

## Basis / References
- Portfolio basis: Radisson Blu Stansted, UN Studio Tower

## Assumptions
- Building-specific survey required before implementation
- Energy audit recommended to quantify baseline and savings

## Implementation Essentials
1. 1) Audit current BMS remote access configuration. 2) Enable VPN access for property management team or configure cloud gateway (BACnet/IP to cloud). 3) Establish change-log protocol — all setpoint changes logged with timestamp and name. 4) Create RACI matrix for who can approve what changes. 5) Train property manager on BMS interface.

## Risks / Constraints
- Operational efficiency measure — modest direct savings, critical for portfolio oversight.

## KPIs
- BMS response time to faults (hrs)
- Contractor callouts (#/month)
- Setpoint changes logged (%)

## M&V Plan (IPMVP Option C with submetering where feasible)
- Pre-installation baseline: 90-day continuous monitoring
- Post-installation: compare same period following year (weather-normalised)
- IPMVP Option C: Whole-building metering with regression analysis

## Costs & Payback (indicative)
- Payback: 1–6 months
- Cost: Requires building-specific survey and contractor pricing
